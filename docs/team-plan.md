# 五人团队分工

本项目采用“项目管理—数据工程—数据分析—可视化—测试文档”五个岗位协作。五名成员共同参与需求讨论、阶段汇报和最终答辩，每个人不仅负责自己的模块，也需要理解完整项目流程。

## 1. 组员一：项目负责人、需求分析与总体设计

组员一负责确定“基于 UCI Bike Sharing 数据集的共享单车租赁需求分析与可视化系统”这一项目题目，分析运营人员对高峰时段、天气影响和用户结构的实际需求，完成项目目标、功能需求和非功能需求设计；负责制定项目进度、分配任务、组织阶段讨论，协调成员之间的接口；负责总体技术路线、系统模块划分和最终报告整合；在最终答辩中介绍项目背景、需求分析、总体架构和项目成果。

对应成果：`docs/requirements.md`、`docs/system-design.md`、`docs/final-report.md` 的项目背景和需求章节。

## 2. 组员二：数据获取、数据字典与数据清洗

组员二负责从 UCI Machine Learning Repository 获取 Bike Sharing 数据集，核对数据集许可、来源、时间范围和文件结构；负责阅读 `Readme.txt`，整理 `hour.csv` 和 `day.csv` 的字段含义，编写数据字典；负责实现数据读取、字段完整性校验、日期转换、数值类型转换、缺失值处理和异常记录处理；负责检查清洗前后的记录数量，确保数据处理过程可复现，并在答辩中说明数据来源和清洗规则。

对应成果：`data/raw/uci-bike-sharing/`、`data/raw/README.md`、`src/bikeshare_viz/data/loader.py`、`src/bikeshare_viz/data/cleaner.py`。

## 3. 组员三：指标设计、统计分析与结果解释

组员三负责把业务问题转化为可计算指标，设计小时平均租车量、用户类型平均租车量、天气条件平均租车量、工作日与非工作日租车量等分析指标；负责实现分组聚合和统计计算函数，检查指标计算逻辑；负责对真实数据进行分析，整理 17:00 高峰、注册用户占比、工作日差异和天气影响等主要发现；负责撰写实验报告中的数据处理结果和结果讨论，并说明描述性分析与因果结论之间的区别。

对应成果：`src/bikeshare_viz/analysis/metrics.py`、`docs/final-report.md` 第 5—6 节、生成图表的数据依据。

## 4. 组员四：可视化设计与成果展示

组员四负责根据分析指标选择合适的图表类型：用折线图展示小时需求变化，用柱状图展示用户类型差异和天气影响；负责统一图表尺寸、颜色、标题、坐标轴和输出命名；负责运行程序生成 `reports/figures/` 中的 PNG 图表，检查图表是否清晰、是否存在标签缺失或数据误读；负责制作答辩展示顺序，现场讲解图表和运营含义。

对应成果：`src/bikeshare_viz/visualization/charts.py`、`reports/figures/`、`docs/code-structure.svg`、实验报告可视化章节。

## 5. 组员五：测试、工程质量与文档整理

组员五负责编写和维护 pytest 测试，验证字段校验、真实数据记录数量、租车量有效性和小时统计完整性；负责在干净环境中按照运行手册复现项目，检查依赖、路径和命令行参数；负责整理 README、运行手册、技术调研报告、代码结构图和提交清单；负责进行最终质量检查，确认源代码、真实数据、图表、报告和参考资料齐全；在答辩中演示测试通过结果和项目复现过程。

对应成果：`tests/test_bikeshare.py`、`README.md`、`docs/operation-manual.md`、`docs/tech-research.md`。

## 6. 团队共同工作

五名成员共同完成选题讨论、需求评审、阶段汇报、代码互相讲解、实验结果核对和最终答辩。组员一负责整合不代表其他成员不参与报告；每位成员都应能够说明“数据从哪里来、如何清洗、指标如何计算、图表如何生成、结论有什么限制”。

## 7. 报告中可直接使用的团队贡献表

| 成员 | 个人贡献 |
| --- | --- |
| 组员一 | 负责项目选题、需求分析、总体设计、进度协调和最终报告整合。 |
| 组员二 | 负责 UCI 数据获取、数据字典、字段校验和数据清洗模块。 |
| 组员三 | 负责分析指标设计、统计计算、数据结论和结果解释。 |

提交前仅需把“组员一—组员五”替换为五位同学的真实姓名和学号。
