# 基于 UCI Bike Sharing 数据集的共享单车租赁需求分析与可视化系统

## 摘要

本项目面向城市共享单车运营分析场景，使用 Python 对 2011—2012 年 Capital Bikeshare 系统的小时级租车数据进行清洗、统计分析和可视化。项目围绕“什么时候需求最高”“天气是否影响租车量”“注册用户和临时用户有何差异”三个问题设计分析流程，最终生成小时需求、用户结构和天气影响三类图表。

关键词：Python；pandas；共享单车；数据分析；数据可视化；租车需求

## 1 项目背景与需求分析

共享单车系统需要根据时间、季节、工作日和天气变化安排车辆调度和运维资源。若仅依靠经验进行调度，容易造成高峰期车辆不足、低需求区域车辆闲置等问题。因此，本项目构建一个离线可复现的数据分析原型，为共享单车需求判断提供数据依据。

### 1.1 用户角色

| 用户 | 需求 |
| --- | --- |
| 运营人员 | 识别高峰时段、天气影响和用户结构，为调度与营销提供依据 |

| 项目开发成员 | 通过模块化代码协作开发、测试和维护 |

### 1.2 功能需求

1. 读取并校验 UCI Bike Sharing 小时级 CSV 数据。
2. 将日期、类别和数值字段转换为可分析类型，处理异常记录。
3. 计算小时平均租车量、用户类型平均租车量和天气条件平均租车量。
4. 生成格式统一、带标题和坐标轴的 PNG 图表。
5. 通过命令行指定输入文件和输出目录，保证结果可复现。
6. 提供自动化测试，验证数据读取、清洗和统计流程。

## 2 数据来源与数据字典

数据来自 [UCI Machine Learning Repository Bike Sharing Dataset](https://archive.ics.uci.edu/dataset/275/bike%2Bsharing%2Bdataset)，数据集编号为 275，许可为 CC BY 4.0。数据包括 `hour.csv` 和 `day.csv`，本项目主要使用 `hour.csv` 的 17,379 条小时记录，时间范围为 2011-01-01 至 2012-12-31。

| 字段 | 含义 | 类型 | 用途 |
| --- | --- | --- | --- |
| instant | 记录编号 | 整数 | 数据标识 |
| dteday | 日期 | 日期 | 时间分析 |
| season | 季节编码 | 类别 | 季节对比 |
| yr | 年份编码 | 类别 | 年度对比 |
| mnth | 月份编码 | 类别 | 月度趋势 |
| hr | 小时 | 类别 | 高峰时段分析 |
| holiday | 是否节假日 | 二值 | 节假日影响 |
| weekday | 星期 | 类别 | 周期分析 |
| workingday | 是否工作日 | 二值 | 工作日对比 |
| weathersit | 天气编码 | 类别 | 天气影响 |
| temp | 归一化温度 | 实数 | 相关性/建模 |
| atemp | 归一化体感温度 | 实数 | 相关性/建模 |
| hum | 归一化湿度 | 实数 | 相关性/建模 |
| windspeed | 归一化风速 | 实数 | 相关性/建模 |
| casual | 临时用户租车量 | 整数 | 用户结构 |
| registered | 注册用户租车量 | 整数 | 用户结构 |
| cnt | 总租车量 | 整数 | 核心目标指标 |

## 3 技术路线与方案选择

数据处理采用 pandas，图表采用 matplotlib，测试采用 pytest。处理流程为：

```text
hour.csv → 字段校验 → 类型转换 → 缺失/异常处理 → 指标聚合 → PNG 图表
```

项目没有把预测模型作为核心功能，原因是课程重点为“数据分析与可视化”，先保证分析过程透明、结果可解释，再将预测作为扩展方向。

## 4 系统设计

### 4.1 模块设计

- `data/loader.py`：读取 CSV，并检查必需字段。
- `data/cleaner.py`：转换日期和数值字段，删除不完整记录，计算用户占比。
- `analysis/metrics.py`：提供小时和天气分组统计函数。
- `visualization/charts.py`：统一生成 PNG 图表。
- `main.py`：解析命令行参数并编排完整流程。
- `tests/`：验证真实数据的记录数量和核心指标维度。

### 4.2 运行流程

1. 程序从默认路径加载 `hour.csv`。
2. 校验必需字段。
3. 转换日期与数值类型，并删除关键字段为空的记录。
4. 计算小时、用户类型和天气分组指标。
5. 输出三张图表到 `reports/figures/`。

## 5 数据处理实现

清洗阶段将 `dteday` 转为 pandas 日期类型，将小时、天气、温度、湿度和租车量字段转为数值类型。对于无法转换或关键字段缺失的记录予以删除。由于数据集本身无缺失值，清洗后仍保留 17,379 条记录。

项目同时计算：

```text
临时用户占比 = casual / cnt
```

当总租车量为 0 时使用缺失值替代分母 0，避免产生无穷值。

## 6 分析结果

- 小时记录数：17,379 条
- 总租车量：3,292,679 次
- 单条小时记录平均租车量：189.46 次
- 注册用户占总租车量：81.17%
- 临时用户占总租车量：18.83%

按小时求平均后，17:00 的平均租车量最高，为 461.45 次；早高峰 8:00 也表现出较高需求。这说明工作日通勤和下班时段是重要需求窗口，可用于制定高峰前调度策略。

工作日小时平均租车量为 193.21 次，非工作日为 181.41 次。晴朗天气平均租车量为 204.87 次，小雨或小雪为 111.58 次，强降雨或大雪为 74.33 次。总体上天气越恶劣，租车量越低，但该结论属于描述性分析，不应直接解释为严格因果关系。

## 7 可视化结果

- `rentals_by_hour.png`：24 个小时的平均租车量。
- `rentals_by_user_type.png`：临时用户和注册用户平均租车量。
- `rentals_by_weather.png`：四类天气条件下的平均租车量。

所有图表使用统一尺寸、标题、坐标轴和颜色体系，适合直接插入实验报告。

## 10 局限性与改进方向

1. 数据按小时聚合，无法分析具体站点之间的流量流向。
2. 数据来自 2011—2012 年，不能代表当前城市交通状况。
3. 天气字段是编码后的类别，尚未接入实时气象 API。
4. 当前输出为静态 PNG，后续可以使用 Streamlit 或 Plotly 构建交互式页面。
5. 后续可使用随机森林、梯度提升或时间序列模型进行需求预测，并通过 MAE、RMSE 评价模型效果。
