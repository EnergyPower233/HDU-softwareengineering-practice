## 成员 1：项目背景、整体方案与数据库（约 2 分钟）

各位老师好。我们展示的项目是“共享单车租赁需求分析、数据库查询与可视化大屏系统”。

我们没有把项目做成单纯的图表展示，而是按一条完整的数据链路实现：从真实 CSV 数据出发，完成数据分析、SQLite 数据库存储、查询接口和浏览器端可视化展示。这样做的目的，是让分析结果不仅能写进报告，也能被前端页面直接使用。

项目使用两类数据：UCI 的小时级数据用于通用统计分析；Kaggle 整理后的 `bike_data.csv` 用于数据库和数据大屏。后者包含时间、季节、天气、温湿度、临时用户、注册用户和总租车量等字段，适合回答运营中最常见的几个问题：哪个时段需求最高、天气如何影响租车量、用户构成有什么特点。

在项目结构中，后端部分位于 `src/bikeshare_viz/database/`。`init_db.py` 负责读取 CSV、建立 SQLite 数据库、创建 `bike_usage` 表并建立索引；`db_helper.py` 封装 KPI、天气、小时统计查询；`api.py` 提供本地 JSON 接口。

## 成员 2：数据处理与分析结果（约 2 分钟）

数据分析部分的重点不是简单求和，而是保证数据处理逻辑可复现。

程序首先在 `loader.py` 中检查输入字段是否完整；随后在 `cleaner.py` 中完成日期解析、数值字段转换、缺失值处理和排序。这样的处理方式使代码能够适配同结构数据，而不依赖手工修改。

分析模块中，`metrics.py` 主要计算两个维度：按小时统计平均租车量，按天气类型统计平均租车量。这里我们使用平均值而不是直接比较总量，是因为不同分组的记录数可能不同，平均值更适合描述典型时段或典型天气下的需求水平。

根据 UCI 小时级数据，项目共分析了 17,379 条记录，总租车量为 3,292,679 次。17 点的平均租车量最高，约为 461 次；这与下班通勤高峰相符。注册用户占总租车量约 81%，说明稳定用户是系统的主要使用群体。

天气方面，晴朗天气的平均租车量明显高于雨雪天气。这里需要强调，这是一项描述性分析，我们只能说明数据中存在这种变化趋势，不把它直接表述为严格因果关系。

## 成员 3：前端数据大屏与可视化（约 2 分钟）

前端部分位于 `web/dashboard/`。页面使用 HTML、CSS、JavaScript 和 ECharts 实现，不依赖复杂框架，便于部署和答辩现场演示。

`process_data.py` 会从 `bike_data.csv` 中计算总租车数、日均租车数、最高单日租车数、注册用户占比、月度趋势、小时趋势、季节差异和温度散点数据，并输出为 `data.json`。页面通过 `fetch('data.json')` 读取这些结构化数据，再由 ECharts 绘制图表。

大屏顶部的四张指标卡片提供总体情况；中间的月度趋势图用于观察需求变化；小时柱状图用于识别高峰时段；季节图和温度散点图用于观察环境因素；饼图展示用户构成。

这样设计的好处是，数据处理和页面渲染是分离的。后续替换新的 CSV 数据，只需要重新运行 `process_data.py`，页面就会自动使用新的 `data.json`，不需要修改图表逻辑。

## 成员 5：技术调研、项目总结与扩展（约 1 分 30 秒）

在技术选择上，我们优先保证项目可复现和可解释。数据处理采用 pandas，数据库采用 SQLite，前端图表采用 ECharts。它们的共同特点是部署成本低、接口清晰，适合课程项目从数据到展示的完整实现。

项目目前的价值主要体现在三个方面：第一，能够快速识别共享单车的时段需求和用户结构；第二，能够通过天气统计为运营安排提供参考；第三，分析、数据库和前端三部分已经形成闭环，数据可以从 CSV 进入数据库，也可以进入可视化页面。

项目也有明确边界。当前数据是按小时聚合的，没有起点站和终点站，因此没有绘制站点流向地图；天气影响是统计关联，不是因果推断；前端目前读取静态 JSON，后续可以直接切换为调用本地 API。

下一步可以增加三项能力：接入实时天气或共享单车数据、使用随机森林或时间序列模型预测需求、将大屏升级为可筛选的交互式管理页面。

## 常见追问简答

**为什么同时使用 UCI 和 Kaggle 数据？**

UCI 数据用于完整的小时级分析验证；Kaggle 整理数据字段更适合直接导入数据库和生成前端数据大屏。两者都用于共享单车需求分析，但承担的模块不同。

**为什么使用 SQLite？**

SQLite 不需要单独部署数据库服务，数据库文件可直接随项目提交，适合课程项目演示；同时支持标准 SQL 查询和索引，能够体现建库、导入和查询接口的完整过程。

**前端为什么不直接查数据库？**

浏览器不能直接安全访问 SQLite 文件。当前页面读取预生成的 `data.json`；后续可改为调用 `api.py` 的 JSON 接口，实现前后端解耦。

**项目最核心的工程设计是什么？**

将数据分析、数据库查询和前端展示分层实现。每层职责单一，便于测试、替换数据源和多人协作。
